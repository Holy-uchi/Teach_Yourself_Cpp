## 第50問 `std::atomic<int>` によるロックフリー更新

【問題】
以下の仕様を満たすコードを書け。

【与えられるもの】

```cpp
#include <iostream>
#include <thread>
#include <vector>
#include <atomic>
```

【要件】

* `std::atomic<int> counter{0};` を用意せよ
* 複数スレッド（2〜4個）で `counter++` を繰り返せ（各スレッド10000回）
* 最終的な値を出力せよ

【制約】

* `mutex` は使用禁止
* `atomic` を必ず使うこと

【確認ポイント】

* 結果が常に正しく（例：20000）なること
* データレースが発生しないこと
* 前章の非atomic版との違いを説明できること

【この問題の主眼】

* `std::atomic` によって単純な更新はロックなしで安全にできることを理解する

## 第51問 mutex と atomic の使い分け基準

【問題】
以下の2つのケースに対して、`atomic` と `mutex` のどちらを使うべきか判断せよ。

【与えられるもの】

ケースA：

```cpp
// 単純なカウンタのインクリメント
counter++;
```

ケースB：

```cpp
// 複数の変数を同時に更新する
balance -= amount;
history.push_back(amount);
```

【要件】

* 各ケースに対して適切な同期方法を選べ
* 理由を説明せよ

【制約】

* 実装は不要
* 「なぜそれが必要か」を明確にすること

【確認ポイント】

* 単一変数の更新なら atomic が適していること
* 複数操作の一貫性には mutex が必要であること
* 操作の粒度で判断できていること

【この問題の主眼】

* atomic と mutex は用途が異なることを理解する
* 「何を守るか」で同期手段を選ぶ感覚を身につける

## 第52問 複合操作で atomic だけでは不十分なケース

【問題】
以下のコードには問題がある。説明し、修正せよ。

【与えられるもの】

```cpp
#include <atomic>

std::atomic<int> balance{100};

void withdraw(int amount) {
    if (balance >= amount) {
        balance -= amount;
    }
}
```

【要件】

* このコードの問題点を説明せよ
* 正しく動作するように修正せよ

【制約】

* atomic はそのまま使ってよい
* 必要なら mutex を追加してよい

【確認ポイント】

* check-then-act が非原子的であることを説明できること
* 同時実行で不正な引き出しが起きることを理解していること
* mutexで修正できること

【この問題の主眼】

* atomic は「単一操作」しか保証しないことを理解する
* 複合操作には別の同期が必要であることを理解する

## 第53問 ロックか設計変更かを判断する問題

【問題】
以下の設計を改善せよ。

【与えられるもの】

```cpp
// 複数スレッドが共有カウンタに頻繁に書き込む
// そのたびに mutex でロックしている
```

【要件】

* この設計の問題点を説明せよ
* 改善案を1つ以上提示せよ
* 必ずしも mutex を使い続ける必要があるか検討せよ

【制約】

* atomic を使う案でもよい
* データ分割などの設計変更も可

【確認ポイント】

* ロック競合がボトルネックになることを理解していること
* atomicで解決できるケースを見極められること
* 設計変更（スレッドローカルなど）を提案できること

【この問題の主眼】

* 同期手段の選択だけでなく、設計で問題を解決する視点を持つこと

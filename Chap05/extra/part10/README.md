# 第10章 総合設計問題（3問）

---

## 第58問 所有権モデル（unique / shared / weak / borrow）の選択問題

【問題】
以下のシステム要件に対して、各関係に適切なポインタ種別を設計せよ。

【与えられるもの】

```
// システム構造

Application
 ├─ owns → Config
 ├─ owns → Logger
 ├─ owns → WorkerPool

Worker
 ├─ refers → Config
 ├─ refers → Logger
 ├─ optionally refers → Application

WorkerPool
 ├─ owns → Workers (複数)
```

【要件】

* 各関係に対して以下を決定せよ

  * `unique_ptr`
  * `shared_ptr`
  * `weak_ptr`
  * 生ポインタ / 参照（borrow）
* なぜその選択になるかを説明せよ

【制約】

* 不要な `shared_ptr` 使用は禁止
* 所有関係と参照関係を明確に分離すること
* 循環参照を発生させないこと

【確認ポイント】

* `Application → Config/Logger/WorkerPool` が単一所有であること
* `WorkerPool → Worker` が所有であること
* `Worker → Config/Logger` が非所有参照であること
* `Worker → Application` が weak_ptr などで循環回避されていること
* 「なぜshared_ptrではないか」を説明できること

【この問題の主眼】

* 所有権モデルを構造から設計できること
* `shared_ptr` を例外的に使う判断ができること

## 第59問 RAIIと並行処理を組み合わせた安全設計

【問題】
以下の仕様を満たすクラス設計を行え。

【与えられるもの】

```
// 要件

- 複数スレッドからアクセスされるカウンタ
- increment と get がある
- データレースは絶対に起こしてはいけない
- 例外安全であること
```

【要件】

* クラス設計（メンバ・メソッド）を示せ
* 適切な同期手段を選択せよ
* RAIIを用いてロック管理を行え

【制約】

* 手動 `lock()` / `unlock()` は禁止
* `lock_guard` または同等のRAII手段を使うこと
* `atomic` を使うかどうかは設計判断に委ねる

【確認ポイント】

* データレースが発生しないこと
* ロック漏れがないこと
* 例外が発生してもロックが解放されること
* 過剰なロックになっていないこと

【この問題の主眼】

* RAIIと並行処理を統合して設計できること
* 「安全」と「性能」のバランスを考えられること

## 第60問 所有権・ライフタイム・同期を統合した最終設計問題

【問題】
以下のシステムを設計せよ。

【与えられるもの】

```
// システム要件

- Task を処理する非同期システム

- TaskManager
    - Task を生成する
    - Task を複数スレッドに配布する

- Worker（複数）
    - Task を受け取り処理する

- Task
    - 処理中にキャンセルされる可能性がある
    - 複数箇所から参照される可能性がある

- ログ出力あり（Logger）
```

【要件】

以下をすべて設計せよ：

1. 各オブジェクト間の所有関係
2. 使用するポインタ種別
3. スレッド間でのデータ共有方法
4. Task の寿命管理方法
5. キャンセル時の安全な処理方法

【制約】

* `unique_ptr`, `shared_ptr`, `weak_ptr` を適切に使い分けること
* 循環参照は禁止
* データレースは禁止
* ダングリング参照は禁止

【確認ポイント】

* Task の寿命が安全に管理されていること
* Worker が終了後に不正アクセスしないこと
* キャンセル時に安全に処理が止まること
* Logger の扱いが適切であること（共有 or 非所有）
* 同期方法が明確であること

---

## 評価基準（この問題のみ特別）

この問題は以下で評価する：

### 所有権

* [ ] 所有者が明確
* [ ] 不要な shared_ptr がない

### ライフタイム

* [ ] ダングリングが発生しない
* [ ] 早期解放・遅延解放が適切

### 並行性

* [ ] データレースがない
* [ ] 同期が適切

### 設計品質

* [ ] 過剰設計でない
* [ ] 責務分離ができている

---

【この問題の主眼】

* 所有権・ライフタイム・同期を統合して設計できること
* 実務レベルの設計判断を行えること

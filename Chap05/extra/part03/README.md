## 第15問 `shared_ptr` の生成と共有所有モデルの把握

【問題】
以下の仕様を満たすコードを書け。

【与えられるもの】

```cpp
#include <iostream>
#include <memory>
#include <string>

struct Tracer {
    std::string name;

    Tracer(const std::string& n) : name(n) {
        std::cout << "construct: " << name << '\n';
    }

    ~Tracer() {
        std::cout << "destruct: " << name << '\n';
    }
};
```

【要件】

* `Tracer("A")` を管理する `std::shared_ptr<Tracer> p1` を作成せよ
* `p1` をコピーして `p2` を作成せよ
* `p1->name` と `p2->name` をそれぞれ出力せよ
* スコープ終了時に `Tracer` が1回だけ破棄されることを確認せよ

【制約】

* `shared_ptr` を使用すること
* `unique_ptr` は使用禁止
* `delete` は使用禁止

【確認ポイント】

* `p1` と `p2` が同じオブジェクトを指していること
* デストラクタが1回しか呼ばれないこと
* 複数の所有者が存在するモデルを理解していること

【この問題の主眼】

* `shared_ptr` は複数の所有者で1つのオブジェクトを共有する仕組みであることを理解する

## 第16問 参照カウントの増減をコードで観察する

【問題】
以下の仕様を満たすコードを書け。

【与えられるもの】

```cpp
#include <iostream>
#include <memory>
```

【要件】

* `std::shared_ptr<int> p1 = std::make_shared<int>(42);` を作成せよ
* 以下の3時点で `use_count()` を出力せよ

  1. 生成直後
  2. `p2 = p1` コピー後
  3. `p2` がスコープを抜けた後
* 出力が `1 → 2 → 1` になることを確認せよ

【制約】

* `make_shared` を使うこと
* 出力順序を明確にすること

【確認ポイント】

* 参照カウントが増減することを正しく観察できていること
* スコープによってカウントが減ることを理解していること

【この問題の主眼】

* `shared_ptr` の本質は「参照カウント」であることを理解する
* 寿命管理がカウントに依存することを理解する

## 第17問 `make_shared` のメモリ配置と利点

【問題】
以下の仕様を満たすコードを書け。

【与えられるもの】

```cpp
#include <iostream>
#include <memory>

struct Data {
    int x;

    Data(int v) : x(v) {
        std::cout << "construct\n";
    }

    ~Data() {
        std::cout << "destruct\n";
    }
};
```

【要件】

* `new Data(10)` を使った `shared_ptr` の生成と、
  `make_shared<Data>(10)` を使った生成をそれぞれ書け
* 両方のコードをコメントで並べて比較できるようにせよ
* 実際に使用するのは `make_shared` の方とする

【制約】

* 両方の生成方法を書くこと
* 最終的に使うのは `make_shared` にすること

【確認ポイント】

* `make_shared` を使う書き方が理解できていること
* 「2回の確保 vs 1回の確保」という違いを説明できること

【この問題の主眼】

* `make_shared` は効率面・安全面で基本的に推奨される生成方法であることを理解する

## 第18問 コピーが引き起こすカウント増加とコスト感覚

【問題】
以下の仕様を満たすコードを書け。

【与えられるもの】

```cpp
#include <iostream>
#include <memory>
```

【要件】

* `shared_ptr<int>` を作成し、3回コピーして複数の変数に保持させよ
* コピーのたびに `use_count()` を出力せよ
* 最終的なカウントを出力せよ

【制約】

* コピーによる増加を明示的に確認すること
* move は使用しないこと

【確認ポイント】

* コピーごとにカウントが増加すること
* 最終的なカウントが期待通りであること
* コピーは軽い操作ではないという感覚を持てていること

【この問題の主眼】

* `shared_ptr` のコピーは単なる値コピーではなく、状態を変える操作であることを理解する
* 無意識コピーの危険性を認識する

## 第19問 関数引数での `shared_ptr` 受け渡し（値渡し/参照渡しの差）

【問題】
以下の仕様を満たすコードを書け。

【与えられるもの】

```cpp
#include <iostream>
#include <memory>

void byValue(std::shared_ptr<int> p) {
    std::cout << "inside byValue: " << p.use_count() << '\n';
}

void byConstRef(const std::shared_ptr<int>& p) {
    std::cout << "inside byConstRef: " << p.use_count() << '\n';
}
```

【要件】

* `shared_ptr<int>` を1つ作成せよ
* `byValue` と `byConstRef` をそれぞれ呼び出せ
* 呼び出し前・中・後の `use_count()` をすべて出力せよ

【制約】

* 両方の関数を呼び出すこと
* 出力順を分かりやすくすること

【確認ポイント】

* 値渡しではカウントが増えること
* 参照渡しではカウントが増えないこと
* 呼び出し後に元のカウントに戻ること

【この問題の主眼】

* API設計において、値渡しはコストと意味を持つことを理解する
* `shared_ptr` の受け渡し方を意識的に選べるようになること

## 第20問 共有所有が“必要な状況”を具体例から選別する

【問題】
以下の2つの状況に対して、`unique_ptr` と `shared_ptr` のどちらを使うべきか判断せよ。

【与えられるもの】

状況A：

```cpp
// 1つのクラスだけが Resource を所有し、他は参照するだけ
```

状況B：

```cpp
// 複数のオブジェクトが同じ Resource を保持し、
// 全ての参照がなくなるまで生存させたい
```

【要件】

* 各状況に対して適切なポインタ種別を選べ
* 理由を簡潔に説明せよ

【制約】

* 感想ではなく「所有者の数」に基づいて説明すること
* 実装は不要

【確認ポイント】

* 単一所有なら `unique_ptr` を選べること
* 共有所有が必要な場合のみ `shared_ptr` を選べること
* 不必要に `shared_ptr` を使わない判断ができること

【この問題の主眼】

* `shared_ptr` はデフォルトではなく例外であるという感覚を身につける

## 第21問 `unique_ptr` と `shared_ptr` の設計選択比較

【問題】
以下の2つの設計案のうち、より適切なものを選べ。

【与えられるもの】

案A：

```cpp
std::shared_ptr<Resource> create();
```

案B：

```cpp
std::unique_ptr<Resource> create();
```

条件：

* 呼び出し側が唯一の所有者になる
* 他の場所で共有する必要はない

【要件】

* 適切な案を選べ
* 不適切な案の問題点を説明せよ

【制約】

* 条件から論理的に判断すること
* 実装は不要

【確認ポイント】

* `unique_ptr` を選べること
* `shared_ptr` が過剰である理由を説明できること
* 「とりあえず shared_ptr」という誤用を避けられること

【この問題の主眼】

* 設計において「どのポインタを選ぶか」が重要な判断であることを理解する
* `unique_ptr` をデフォルト選択にできるようにする
